# 使用指南

## 功能一览

[README](../README.md) 里那张表是压缩版，这里是完整版。

| 分类 | 能力 |
|---|---|
| 浏览 | 歌单广场、歌手列表（可按地区筛选）、排行榜、个人云端歌单 |
| 检索 | 单曲搜索（登录后可搜）；结果按服务端相关性排序，`M` 加载更多 |
| 播放 | 播放 / 暂停 / 上一首 / 下一首 / 进度跳转（±5 秒）/ 音量（±5%）/ 静音 |
| 播放模式 | 顺序、列表循环、单曲循环、随机 |
| 歌词 | 逐字歌词（KRC）、译文 / 音译（多语言轨）、卡拉 OK 式居中滚动、时间偏移微调（±100 ms） |
| 逐字高亮 | 解析 KRC 的每字时间戳，按**每个字自己的进度**在底色与强调色之间插值——边界字是渐变过渡，仿 Apple Music 的推进；非当前行按距离线性变暗 |
| 可视化 | **真频谱**：对音频线程采集的采样做 FFT 后按对数分频（40Hz–16kHz），贝斯亮左、镲片亮右；非随机动画 |
| 播放队列 | 追加单曲（`a`）、插播下一首（`i`）、整列表加入（`A`）、移除单曲（`x`）、清空（`X`） |
| 云端歌单 | 收藏单曲（`s`）、整个队列同步（`S`）、从歌单移除（`d`）、删除歌单（`D`）、新建歌单（`N`） |
| 登录 | **应用内扫码**（`L`），二维码直接画在终端里，无需额外工具 |
| 概念版 VIP | **每日自动领取**（启动时 / 登录后 / 切到概念版时各试一次，一天只领一次），`V` 手动重试；`我的资料`里显示领取状态，鼠标点那一行也行 |
| 输入 | 键盘 + 鼠标（点击选中、双击激活、滚轮、点进度条跳转） |
| 缓存 | 音频落盘缓存 + LRU 上限回收；`C` 一键清空 |
| **网络** | **瞬时故障自动重试**：连接被拒 / 连接被重置 / 响应体截断 / 408 / 429 / 5xx 会重试（共 3 次尝试，间隔 300ms → 900ms）；超时、业务错误码、其它 4xx 不重试。写操作（收藏 / 删歌单 / 领 VIP）一律不重试 |
| 外观 | 6 套主题（冷蓝 / 石墨 / 日落 / 森林 / 霓虹 / 暗紫），各有真彩与 16 色两版 |
| 设置页 | `,` 打开：主题、音质、播放模式、刷新间隔、歌词偏移、每页条数、缓存上限、16 色、歌词面板、侧边导航、下载目录、封面铺满方式、**输出设备**；改完立即落盘 |
| 单曲下载 | `W` 把当前播放的歌曲下载到设置里选的目录（默认 `~/Music`） |
| **桌面集成** | **MPRIS**：注册为 `org.mpris.MediaPlayer2.kugou-tui`，状态栏/媒体控件/`playerctl` 可直接控制并显示封面；**系统托盘**：注册为 `org.kde.StatusNotifierItem` 并带右键菜单（播放/暂停、上一首、下一首、最小化/显示窗口——后者仅 niri），Quickshell / waybar / KDE 等状态栏会显示图标，悬停显示当前曲目 |

支持的音频格式由 rodio 决定：**MP3、FLAC、M4A/MP4、OGG(Vorbis)、WAV**。
可选的播放音质见[配置文件](CONFIGURATION.md)的 `quality`。

## 使用说明

### 界面布局

```
┌──────────┬──────────────────────────────┐
│ 侧边栏    │ Primary（搜索框 / 条目列表）    │
│ 分组导航  ├──────────────────────────────┤
│ +连接状态 │ Secondary（歌曲列表） │ 歌词    │
│          ├──────────────────────────────┤
│          │ 播放队列                       │
├──────────┴──────────────────────────────┤
│  稻香 · 周杰伦 · 魔杰座      下一首 晴天 │
│ ━━━━━━━━━━━━━━━━━━━━━━━━ 1:23 / 4:56    │
└─────────────────────────────────────────┘
```

按 `Tab` / `Shift+Tab` 在「侧边栏 → Primary → Secondary → 队列」之间轮转焦点，
当前有焦点的面板边框会高亮。

**侧边栏**按「正在播放 / 发现 / 我的 / 设置」分组，每个标签带图标并**标出数字键**。
「正在播放」整组排在最前——首页是默认落点、也是用得最多的一页：

```
── 正在播放 ──
>  1  首页
── 发现 ──
   2  搜索
   3  歌单
── 我的 ──
   6  云端
```

> 侧边栏的**显示顺序**和数字键落点故意不同：数字键 1–9/0 对应
> `首页 / 搜索 / 歌单 / 歌手 / 排行榜 / 云端 / 队列 / 音源 / 设置 / 可视化`
> 这个固定顺序（改它会让肌肉记忆全乱），侧边栏只是换了个更好扫的排列，
> 所以每行前标了键名，照着按不会错。
>
> 在侧边栏里按 `↑` `↓` / `j` `k` 走的是**显示顺序**（与屏幕上看到的一致），
> 与数字键落点无关。

导航下面还有三块状态：**连接**（API 地址、音源、登录、指纹、会员）、**播放**
（模式、队列长度、音量）、**缓存**（已用、上限、清理目录）。按优先级排列。

> **矮终端里装不下时会缩写，但不会静默裁掉**：能放几行放几行，最后一行写明
> 还有哪些块没显示，例如 `… 另有 播放 / 缓存`。30 行的终端里通常只放得下
> 「连接」；高度够（约 40 行以上）时三块都能显示，那一行提示也就不出现。
>
> 被略去的信息在别处都有：音量与循环模式在播放条上，队列长度在播放队列的标题上，
> 缓存的已用/上限在设置页里。

**播放条**只占 4 行：一行曲目信息（歌名 · 歌手 · 专辑）+ 一行进度条。
右侧那一小段是「下一首 / 播放状态 / 音量 / 循环模式」。

> **播放条里不放封面**：它总共才 4 行，给封面最多 8×4 格——那个尺寸下专辑图
> 只是一团糊色，既看不清又白占宽度。封面只在**首页**左栏，那里有整块区域可以
> 放大。

**首页**（`1`）的左栏是上下两块：上面封面，下面「我的资料」：

```
┌─ 封面 ──────────┐
│█████████████████│
│█████ 专辑图 █████│
│█████████████████│
├─ 我的资料 ───────┤
│ 惜  惜别  Lv.8   │
│   听过 22 小时   │
└─────────────────┘
```

封面**铺满**整块「封面」面板，不留黑边。终端里的封面区是「多少列 × 多少行」，
换算成像素后几乎永远不是正方形，而专辑封面多是正方形——三者只能取两个，
所以怎么铺由 `cover_fill` 决定（默认居中裁剪）。详见
[配置文件](CONFIGURATION.md#配置文件)的 `cover_fill`。

资料来自 `/user/detail`：昵称、头像、等级、累计听歌时长。**刻意不放**粉丝数、
关注数、访客、星座、勋章——接口返回十几个字段，全摆上来这里就成了数据表。

头像那一格有两种画法，取决于终端：

- **支持 kitty / iTerm2 / sixel 图形协议**的终端画真头像（12 列 × 6 行在典型
  终端里约 108×108 像素，认得出来）；
- **只能退到半块字符**的终端画**昵称首字**。半块模式下那一格只有 24×12 个
  「像素」，任何照片在这个尺寸下都只是一团噪点——比不画还糟。首字只占 3 列，
  省下的宽度留给右边的文字。

三种「没有资料」的情况分开显示：未登录是「未登录（按 L 扫码）」，已登录但还没
取到是「加载中…」，取失败则是失败原因加一行「点这里重试」（点账号区任意位置
重取）。

### 每日领取概念版 VIP

酷狗概念版自带「每天领一天 VIP」的机制（官方客户端里也有），这里把它做成了自动的：
**登录成功后**、**切到概念版音源时**、以及**启动时**各试一次，一天只领一次
（日期记在会话文件里）。领完会顺带把它升级成「畅听 VIP」——只领一天的话权益有限。

`我的资料`里会多出一行状态，只有当前音源是**酷狗概念版**时才显示：

```
│ 测试用户  Lv.8      │
│ 概念版 SVIP · 至 09-24 │
│ 领取今日 VIP · 按 V   │
│ 听过 120 小时 0 分    │
```

* `领取今日 VIP · 按 V` —— 今天还没领，按 `V` 或**鼠标点这一行**去领；
* `领取中…` —— 请求在路上；
* `今日 VIP 已领取` —— 今天领过了，`V` 仍可手动重试。

标准版音源下这一行**不显示**：这是概念版专属接口，摆一个按了没用的入口比不摆更糟。
按 `V` 会提示你先按 `v` 切到概念版。

> 接口带风控。反复失败时提示会告诉你去手机端领取——那边一般能过。
> 官方文档也提醒「尽量别频繁调用」「建议不要领太多天」，所以这里严格按天去重。

**字体**：侧边栏与播放条的图标优先用 Nerd Font，启动时用 `fc-list` 探测一次
（结果缓存）。没装 Nerd Font 会自动退回 ASCII 符号（`>` `*` `@` `#` 等），
不会显示一屏豆腐块。

### 音源（酷狗 / 酷狗概念版）

按 **`v`** 在两个音源之间切换，选择会写进配置文件。切换**不会打断当前播放**——
只换请求地址与身份，播放队列和当前曲目都不动。

侧边栏显示当前音源；`--print-config` 会告诉你它需要的服务端配置：

```
当前音源  : 酷狗概念版（服务端需 platform=lite）
```

两个音源的**登录态与设备标识各自独立**：酷狗两个平台的 token 不通用，所以在 A 音源
扫的码不会自动带到 B 音源。切换后若该音源还没登录，界面会提示，按 `L` 重新扫码即可。

### 网易云音源

网易云走的是 **NeteaseCloudMusicApi**，和酷狗的 KuGouMusicApi 完全是两套服务
（SPlayer、YesPlayMusic 用的也是它）。要用的话得先把它跑起来。

程序只认 `api_base` 这一个地址，**不绑定某个具体实现**——原版 Binaryify 的、
api-enhanced、以及任何接口兼容的 fork 都能用，换服务改这一行就行。下面用的是
`@neteasecloudmusicapienhanced/api`（v4.30.1，接口最全的那个）：

```bash
git clone --depth 1 https://github.com/neteasecloudmusicapienhanced/api-enhanced.git NeteaseCloudMusicApi
cd NeteaseCloudMusicApi && npm install
env PORT=3002 node app.js          # ⚠️ 只认 PORT 环境变量，不认 --port=
```

> 也可以用仓库脚本一步做完：`./scripts/kugou-api-install netease`
> （clone 到 `~/NeteaseCloudMusicApi` + `npm install` + 启动）。

把地址填进配置（默认就是 `3002`）：

```toml
[sources.netease]
enabled = true
api_base = "http://127.0.0.1:3002"
```

**必须再按 `L` 扫码登录**——没登录时云端接口一律返回 `需要登录`。
扫码成功后服务端会下发 cookie（含 `MUSIC_U`），客户端会写到本配置文件的
`[sources.netease].cookie` 里，下次启动自动带上。

> ⚠️ 服务端下发的是**整段 `Set-Cookie`**（含 `Max-Age` / `Expires` / `Path` 属性，
> 多个 cookie 之间用 `;;` 连接），而它读回时**只认「分号 + 空格」这一种分隔**——
> 原样回传会让 `MUSIC_U` 被并进前一个属性段里，服务端认不出登录态：界面显示
> 「登录成功」，云端歌单却永远报「尚未登录」。
>
> 所以客户端存入前会先规范化成 `k=v; k=v` 的形式。**手动往配置里填 cookie 时也要
> 照这个格式填**，不要整段粘贴 `Set-Cookie`。

| 能力 | 网易云 | 酷狗 |
|---|---|---|
| 搜索 / 播放 / 歌词 / 封面 | ✔ | ✔ |
| 云端歌单：列表、曲目 | ✔ | ✔ |
| 云端歌单：加歌、删歌、新建、删除 | ✔ | ✔ |
| 歌单广场、歌手、排行榜 | ✔ | ✔ |

> **不要在手机端**短时间内反复按 `L` 取新二维码——网易云会判「登录频繁」，
> 手机端直接扫不了。本程序**默认每次按 L 都申请一个新会话**，30 秒内连按
> 会被拦下提示剩余等待秒数。

**取链不会受登录限制**——未登录时也能搜歌播放，只有 VIP 专属曲目拿不到。

写操作用的是歌曲 id（不是酷狗歌单条目的 `fileid`），所以从搜索结果也能直接收藏。

配置按音源分别存：

```toml
[sources]
active = "kugou"              # 或 "kugou_concept"

[sources.kugou]
api_base = "http://127.0.0.1:3000"
cookie = "…"                  # 该音源自己的登录态
device_id = "…"               # 该音源自己的 dfid

[sources.kugou_concept]
api_base = "http://127.0.0.1:3001"
```

> 「概念版」不是一个皮肤，而是独立的一套会员与鉴权体系。你的会员属于哪个平台，
> 就要用哪个平台的实例并**在该平台登录**，否则会退化成试听。

### 播放队列

- **排列方向**：歌单与搜索结果默认**倒序**（最后一首排在最上面），按 `o` 切回正序。
  反转的是数据本身，因此界面顺序与播放顺序永远一致。
- **批量加入**：`A` 一次性把当前列表全部追加到队尾（数百首也是一次操作）。
- **清空**：`X` 会先弹确认框，`Enter` 确认后**停止播放**并清空队列。
  只想删一首用 `x`，它不会打断当前播放。

### 登录与云端歌单

按 `L` 弹出二维码，用酷狗 App 扫码即可。成功后凭据写入配置文件，
**界面只提示保存位置，不回显 cookie 内容**——它等价于账号密码。

- 未登录时：浏览与播放全部可用；搜索会返回 `error_code: 152`（需要登录）。
- 云端歌单的写操作（收藏 / 同步 / 移除 / 删除 / 新建）都需要登录。
- 登出：把配置文件里的 `cookie` 行删掉。
- 也可以不扫码，手动传：`--cookie 'token=xxx; userid=xxx'`。

**歌单写操作的限制**（都是接口本身的限制，不是本程序偷懒）：

- `d`（从歌单移除）用的是歌单条目的 `fileid`，只有从歌单接口加载出来的歌才有它，
  搜索结果没有——所以 `d` 只能对歌单里的歌用。
- **重命名没有实现**：`/playlist/update` 额外要求 `total_ver`（歌单版本号），
  而现有的歌单列表接口不返回它。

## 桌面集成（MPRIS 与系统托盘）

> **这一节只适用于 Linux 桌面。** MPRIS 与系统托盘都是 D-Bus 上的接口：
> Windows 没有 session bus，那边相关代码**不参与编译**，界面上也不会出现点了没反应
> 的入口（`--print-config` 会如实显示「系统托盘 : 不可用」）；macOS 上代码会编译，
> 但默认没有 session bus，启动时记一条 WARN 后跳过。
> 其余功能（播放、搜索、歌词、封面、缓存）三个平台完全一致。
>
> 下面提到的「最小化 / 显示窗口」同样只在 niri 下出现，触发入口在**托盘菜单**里；
> 想用键盘绑它，见 [CONFIGURATION.md 的自定义键位](CONFIGURATION.md#自定义键位)。

程序启动时会向 D-Bus session bus 注册 `org.mpris.MediaPlayer2.kugou-tui`。
注册成功后，桌面环境**自动**识别，无需任何配置：

```bash
playerctl -l                      # 应能看到 kugou-tui
playerctl -p kugou-tui status     # Playing / Paused / Stopped
playerctl -p kugou-tui metadata   # 标题、歌手、专辑、封面 URL、时长
playerctl -p kugou-tui play-pause
playerctl -p kugou-tui position 90   # 拖进度条（走 SetPosition）
```

在 Hyprland / DankMaterialShell 这类桌面上，状态栏媒体控件、通知中心、
锁屏界面会直接显示曲目与封面。可用 `dms ipc call mpris list` 确认 DMS 是否看到。

**注意**：桌面环境同时存在多个播放器时（比如浏览器在放视频），会各自打分选
一个显示。若没看到 kugou-tui，先把其它播放器暂停即可。

### 系统托盘

除了 MPRIS，启动时会再注册一个 `org.kde.StatusNotifierItem` 托盘项。状态栏
（Quickshell / waybar / KDE 等）会显示一个音符图标：

- **右键** → 弹出菜单：播放 / 暂停、上一首、下一首、最小化 / 显示窗口（仅 niri）
- **鼠标悬停** → 显示当前曲目
- 播放中状态为 `Active`、暂停时为 `Passive`，部分宿主的显示会跟着变

菜单走 `com.canonical.dbusmenu`（`Menu` 属性指向 `/StatusNotifierItem/menu`）。
**能不能弹出来取决于状态栏自己实现没实现**——Quickshell 的 end4 配置只在
「有菜单」时才响应右键，caelestia 配置则只接了左键、右键压根没实现。后一种情况
用 MPRIS 那套控制（状态栏媒体控件、`playerctl`），功能是一样的。

#### 最小化（niri）

「最小化 / 显示窗口」把 TUI 从平铺布局里收起来但**音乐照常播**，再点一次放回去。
收起来之后键盘就够不着了，这时托盘菜单和 MPRIS 是唯一的控制入口。

终端程序没法自己最小化窗口（Wayland 的 xdg-shell 没有这个请求），所以走 niri 的
`toggle-window-minimized`。程序靠**终端标题**找回自己的窗口：启动时会把标题设成
`kugou-tui`（niri 给的窗口 `pid` 是终端模拟器的，匹配不上）。因此：

- 只在检测到 `NIRI_SOCKET` 时才提供这一项；不是 niri 的话菜单里**没有**它
- 如果你用别的方式改掉了终端标题（比如某些 shell 的标题模板），这项会失效
  ——日志里会记一句「窗口列表里没有标题含 kugou-tui 的窗口」

图标内嵌在程序里（源 `assets/tray.svg`），不依赖系统图标主题。下面三种情况
会自动跳过，各只记一行日志、播放不受影响：没有图形会话（纯 tty、SSH 未转发）、
没有 session bus、状态栏没有提供 `org.kde.StatusNotifierWatcher`。

不想要托盘就加 `--no-tray`，或在配置文件里设 `tray = false`——**重启生效**，
KDE 风格的 watcher 只在进程启动 / 退出时同步托盘项。

没有 D-Bus 的环境（纯 tty、容器）会自动跳过注册，播放功能不受影响。
